# 03 · 录制数据集

[English](03_data_collection.md) · **简体中文**

目标：用主臂遥操作完成任务，录 50 条示范（episode），上传到 Hugging Face Hub。
**这一份数据集四个策略共用**，所以它的质量直接决定后面所有的结果。

## 1. 录下来的到底是什么

`lerobot-record` 以 30 Hz 跑一个循环，每一帧（1/30 秒）记下：

| 键 | 形状 | 含义 | 在训练里的角色 |
|---|---|---|---|
| `observation.images.top` | 480×640×3 | 俯视相机画面 | 输入 |
| `observation.images.wrist` | 480×640×3 | 腕部相机画面 | 输入 |
| `observation.state` | 6 | **从臂**当前 6 个关节角度（归一化后） | 输入 |
| `action` | 6 | **主臂**当前 6 个关节角度 = 发给从臂的目标位置 | 标签（要预测的东西） |
| `task` | 字符串 | 任务描述，比如 "Pick up the blue plush toy and place it in the cardboard box." | SmolVLA / π₀.₅ 的语言输入 |

用深度学习的话说，**这就是一个 (x, y) 数据集**：x = 图像 + 状态（+ 语言），y = 动作。行为克隆（behavior cloning）就是学 x → y 的映射。
PS：`action` 来自主臂，`state` 来自从臂。所以策略学到的是"人在这种画面下会怎么动"。

## 2. 数据集在硬盘上长什么样（LeRobotDataset v3）

```
data\Yufeng1216\so101_pick_place\        （由 scripts/env.ps1 指定；不进 git，Hub 上有一份）
├── meta/
│   ├── info.json        数据集"说明书"：fps、每个键的形状和类型、总帧数、总 episode 数
│   ├── stats.json       每个键的统计量（mean/std/min/max/分位数），训练时用来归一化
│   ├── tasks.parquet    任务描述字符串表
│   └── episodes/        每个 episode 的起止帧、长度等索引
├── data/chunk-000/file-000.parquet     所有帧的 state、action、时间戳（多个 episode 拼在一张表里）
└── videos/
    ├── observation.images.top/chunk-000/file-000.mp4     相机画面压成视频（比存 PNG 小几十倍）
    └── observation.images.wrist/chunk-000/file-000.mp4
```

训练时 LeRobot 按时间戳从 MP4 里解码出对应的帧，和 parquet 里的 state/action 对齐，组成一个 batch。

## 3. 登录 Hugging Face（只需一次）

1. 在 <https://huggingface.co/settings/tokens> 建一个 **Write** 类型的 token。
2. 运行下面的命令，按提示粘贴 token（粘贴时屏幕上不显示，正常），问要不要存成 git credential 时选 `n`：

```powershell
hf auth whoami
```

`whoami` 打印出你的用户名就成功了。**token 只存在本机，不要写进仓库里的任何文件。**

## 4. 设计任务和录制协议

任务：**把蓝色毛绒玩具放进快递盒**。

| 项目 | 设定 |
|---|---|
| episode 数 | 50 |
| 玩具起始位置 | 5 个点 × 每个 10 次（用胶带在桌上标出） |
| 快递盒位置 | 固定不动（用胶带标出四个角） |
| 每条最长 | 30 秒（做完按 → 提前结束） |
| 复位时间 | 25 秒（把玩具放到下一个点，主臂回到起始姿态） |
| 起始姿态 | 每条开始时从臂都在同一个"收起"姿态 |
| 相机 | 固定，录制期间不调整 |

为什么这么设计：

- **多个起始位置**：玩具要是每次都在同一个点，策略只会背下一条轨迹，换个位置就失败。所以这其实是在覆盖输入分布，相当于数据增强。
- **其他条件都固定**：先让问题足够简单，四个策略才可能都学会，后面的比较才有意义。
- **动作风格一致**：每次都用差不多的方式抓（比如从上往下）。示范里的随意变化，对 ACT 这种单峰回归模型来说就是"标签噪声"。
  Diffusion Policy 能处理多模态的示范，这也是后面可以对比的一点。
- **判断信息够不够**：只看相机画面，人自己能不能完成这个任务？能，就说明信息是够的。

### 一条 episode 包含什么

一条 episode = 把任务描述从头到尾**做一遍**，只录"放进去"这一个方向：

```
┌──────────── 录制中（进数据集）────────────────────────────────────┐ ┌──── 复位阶段（不录）────┐
起始姿态 → 移到玩具上方 → 下降 → 夹住 → 抬起 → 移到盒子上方 → 松开 → 回到起始姿态 → 按 →   用手把玩具拿出来，
                                                                                    放到下一个标记点
```

- **把玩具从盒子里拿出来这一步不要用机械臂做**，复位时直接用手拿。不然数据集里会出现两种相反的动作，
  却配着同一句 "place it in the box"，标签就自相矛盾了，VLA 还会学到"语言和动作对不上"。
- **结尾回到起始姿态**：每条的开头和结尾一致，策略也能学会"做完收回来"，而不是停在半空中。

## 5. 遥操作技巧：为什么老是抓不住

刚开始录最常见的问题就是"抓不住"。先看数据（夹爪 0 = 全闭合，100 = 全张开）：

```
t= 5.3s  主臂(action)= 44.1  从臂(state)= 43.4   ← 只张开了 44%
t= 9.3s  主臂(action)=  1.4  从臂(state)=  8.1   ← 主臂已经捏到底，从臂停在 8：玩具夹住了，但只被压扁了一点
```

原因是**从臂夹爪的力是被故意限制的**：LeRobot 把夹爪舵机的最大力矩设成 50%，过载时再降到 25%，防止烧舵机。
毛绒玩具又软，只被压扁一点点，摩擦力很小，一抬就滑掉。这个限制不建议改，所以要靠抓法：

1. **张大再抓**：主臂扳机张到 70–80%，让两个爪子**包住玩具的主体**，而不是只捏到边。
2. **从正上方下去**：先把夹爪移到玩具正上方、手腕朝下，**再垂直下降**，爪尖稍微压到桌面再闭合。
   分成"对准 → 下降 → 闭合 → 抬起"四步，每步都慢一点。
3. **闭合后一直捏紧**：搬运过程中扳机一直按到底，一松手力就没了。
4. **看 Rerun 里的腕部画面对准**：从侧面看很难判断深度，腕部画面里玩具在两个爪子正中间时再闭合。
5. **先空练 10 分钟**：只跑 `.\scripts\robot.ps1 teleop -Cameras` 练手。录进去的每一条都是策略的"教材"，犹豫和反复调整也会被学进去。

## 6. 先录一个测试集（2 条，不上传）

```powershell
.\scripts\robot.ps1 record -Name so101_pick_toy_test -Episodes 2 -EpisodeTime 20 -ResetTime 10 -NoPush
```

PS：同名数据集已经存在时 LeRobot 会拒绝创建，所以重录测试集要换个名字。

录制时的按键（终端窗口不用在前台）：

| 按键 | 作用 |
|---|---|
| **→** 或 `n` | 提前结束这一条，保存，进入复位；复位时按会提前结束复位 |
| **←** 或 `r` | 这条录坏了，丢掉重录 |
| **Esc** 或 `q` | 停止录制，保存并（开了上传的话）上传 |

电脑会用英文语音播报（终端里也会打印），所以要开着声音。整个时间线是这样的（来自 `lerobot_record.py` 源码）：

```
🔊 "Recording episode 0"   ← 开始录，马上操作
│  【录制】最长 episode_time_s 秒：抓 → 放进盒子 → 回起始姿态
├─ 按 →（或时间到）
🔊 "Reset the environment"
│  【复位】reset_time_s 秒，不录；主臂仍然控制从臂。做完可以按 → 跳过剩下的时间
├─ 💾 这时才保存上一条
🔊 "Recording episode 1"
```

关于重录（←）：

- **episode 在复位结束后才保存**，所以录制中或复位中按 ← 都能丢掉它。
- 录制中按 ←：停止录制 → 正常复位 → 🔊 "Re-record episode" → 重录同一编号。
- 复位中按 ←：复位**马上结束**，**立刻**开始重录。所以要先把场景复位好再按。
- 每批**最后一条**没有复位阶段，按 → 就直接保存结束了。不满意的话要在录制中按 ←。
- 编号从 0 开始；用 `-Resume` 追加时编号接着往下数。

录完检查两件事：

1. 终端最后会打印类似 `Cadence (episode 0): 29.88 Hz vs 30 Hz target` 的行，**实际帧率要接近 30 Hz**。
   明显偏低（比如 20 Hz）说明电脑跟不上，关掉其他程序或者降低分辨率。
2. 回放第 0 条，看从臂能不能重复你的动作（**回放时从臂会自己动，注意安全**）：

```powershell
lerobot-replay --robot.type=so101_follower --robot.port=COM3 --robot.id=so101_follower --dataset.repo_id=Yufeng1216/so101_pick_toy_test --dataset.episode=0
```

测试集没问题就可以删掉（在 `data\Yufeng1216\so101_pick_toy_test`）。

## 7. 正式录制（5 批 × 10 条，自动上传）

### 摆场

1. 快递盒四个角用**小块浅色胶带**标出来（或直接粘在桌上），整个项目期间都不动。
2. 5 个玩具起始点：在玩具**正下方**贴小标记（玩具放上去就盖住了，相机基本拍不到）。
   点要在从臂舒服够得到的范围内，彼此相隔 8–15 cm，玩具朝向保持一致。
3. 相机固定后，从录制到最后评估都**不再动**，标记也不要撕。训练和测试时画面不一样就是分布偏移，会直接拉低成功率。
4. 摆好后先遥操作在每个点各抓一次试试。

### 录制

每批 10 条，顺序是 ①①②②③③④④⑤⑤，5 批下来正好每个点 10 条。第一批：

```powershell
.\scripts\robot.ps1 record -Name so101_pick_place -Episodes 10 -ResetTime 25
```

之后每批追加（`-Episodes` 是**这次追加的条数**，不是总数）：

```powershell
.\scripts\robot.ps1 record -Name so101_pick_place -Episodes 10 -ResetTime 25 -Resume
```

节奏：

- 复位 25 秒只是上限：复位时把玩具放好、主臂摆回起始姿态，然后**按 → 跳过剩下的时间**。
- 听到 "Recording episode" **马上**开始动。
- 放进盒子 → 回到起始姿态 → **马上**按 →。
- 录制时手和身体不要进入俯视画面。
- 每批录完，等终端回到提示符（上传完了）再开始下一批。

### 每批录完都检查

```powershell
python scripts/inspect_dataset.py Yufeng1216/so101_pick_place --frames
```

它会给每条 episode 打印时长、空闲占比、开头等待、结尾等待、夹爪最大张开度，并标出可疑的条目（`NO MOTION`、`slow start`、`idle tail` 等）。
`--frames` 会在 `outputs/dataset_check/` 下给每条生成一张缩略图（两路相机各 6 帧），一眼就能看出成没成功。

也可以在网页上看（两路视频和关节曲线同步播放）：
<https://huggingface.co/spaces/lerobot/visualize_dataset?path=/Yufeng1216/so101_pick_place/episode_0>

最终的数据集：50 / 50 条可用，平均约 11 秒，空闲占比 18%，没有开头等待超过 3 秒的。

PS：为什么"开头等待"这么重要？策略学的是"看到这个画面 → 做这个动作"。示范开头要是总空等几秒，
起始画面对应的"正确标签"就变成了"不动"，部署时策略就可能一直停在起始姿态。

## 8. 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `OpenCVCamera(2) failed to set fps=30 (actual_fps=0.0)` | 腕部相机偶尔连不上（线跟着机械臂动被扯到）。重插 USB 再跑。`robot.ps1 record` 会先跑 `scripts/check_cameras.py` 预检查，相机不通就不会开始 |
| `Dataset folder already exists` | 上次运行失败时 LeRobot 已经建了文件夹。打开 `<文件夹>\meta\info.json`：`total_episodes` 是 0 就是空壳，删掉重来；有数据就加 `-Resume` 接着录 |

PS：为什么会留下空壳？`lerobot-record` 是"先建数据集 → 再连相机和机械臂"，所以连接一失败，就留下一个只有 `meta/info.json` 的空文件夹。

## 9. 好数据的检查清单

- [ ] 每条都**成功**完成任务（失败的按 ← 重录，不要留在数据集里）
- [ ] 动作平稳，没有长时间停顿（停顿太多，策略会学会"发呆"）
- [ ] 两个相机里都能看到玩具
- [ ] 5 个起始点的条数大致均衡
- [ ] 整个录制过程中光照和背景不变
