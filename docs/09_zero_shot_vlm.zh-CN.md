# 09 · 免训练基线：VLM 智能体（Claude Haiku 5.5）+ 逆运动学

[English](09_zero_shot_vlm.md) · **简体中文**

PS：状态：已完成。用冻结的智能体（标签 `vlm-agent-frozen`）做了 40 次真机评估：**29/40**，见 §5 和 [results/vlm_agent.zh-CN.md](../results/vlm_agent.zh-CN.md)。

## 1. 为什么要做这组实验

前面四个策略（ACT、Diffusion、SmolVLA、π₀.₅）都**用我们的 50 条示范训练过**：学的是"图像 → 动作"。
另一条路线是**完全不训练**：一个没见过机器人数据的通用视觉语言模型（VLM）看着相机，一步步自己决定怎么做这个任务。
把它放在**同一个任务、同一套评估协议**下比，回答一个很实际的问题：

> 50 条人工示范加上训练，到底比"现成的模型直接做决策"多带来多少？各自在什么情况下失败？

为了比得公平，这个基线不从示范里取任何东西。相机标定、高度、夹爪尺寸都在现场测量，IK 的初值是均匀的网格，40 次评估前冻结所有设置。

## 2. 设计

### 2.1 为什么不让模型直接输出关节角

没训练过的模型不知道这条机械臂的运动学。如果要它直接输出关节角，它只能"看一眼、动一点、再看一眼"，挪几十步，
这是一个长程问题，需要非常大的模型。换成笛卡尔坐标的接口，同一个任务只要 5–10 次决策左右
（到玩偶上方、下降、闭合、抬起、移到箱子上方、松开），小而便宜的模型就能胜任。

IK 在这里相当于"司机"（就像方向盘把"往左"变成车轮的角度），不做任何任务上的决策。
已发表的免训练系统也是这么搭的（Code as Policies、VoxPoser、MOKA、ReKep、Gemini Robotics-ER）：大模型做决策，通用的笛卡尔 / IK 层来执行。

| | 谁来决定 |
|---|---|
| 在哪抓、张多大、抬多高、走什么路线、什么时候松开、要不要重试、什么时候放弃 | **VLM** |
| 把"夹爪移到 (x, y, z)"换算成关节角 | IK（§3.6） |
| 工作区范围、不能扎进桌面、关节速度上限 | 安全层（§3.7） |

### 2.2 工具

| 工具 | 作用 |
|---|---|
| `look()` | 返回俯视图、腕部图和状态 |
| `move_to(x, y, z)` | 夹爪沿直线移动；(x, y, z) 是**两个指尖的中点**，单位是桌面坐标 cm，z 是离桌面的高度 |
| `gripper(opening)` | 0 = 闭合 … 100 = 全开 |
| `done(success, reason)` | 结束这次尝试，附上模型自己的判断 |

`move_to` 和 `gripper` 执行完直接返回新的图像和状态，所以**一次模型调用 = 一个动作**。这是闭环的：每个动作的结果模型都先看到，再决定下一步。

### 2.3 模型看到什么

- **俯视图叠了 5 cm 的网格**，标的是桌面坐标（cm）。模型直接从图上读位置，不用自己猜像素比例。
  红点是夹爪正下方的桌面位置，一条红色短线连着两个指尖。
- **腕部图**：近距离看玩偶在不在两指中间。
- **状态文字**：夹爪位置，夹爪开度的指令值和实测值。
  如果手指夹住了玩偶，实测开度会明显大于指令值（玩偶挡着）；闭合到 1 左右，就是没夹到。
  模型就是靠这一个数知道自己手里有没有东西。
- **被挡住的动作**：如果夹爪停下的位置离目标超过 2 cm（手指或者夹着的玩偶撞到箱壁，舵机就停了），结果里会写明。

prompt 里只有事实：任务、坐标约定、夹爪结构、用尺子量的尺寸（玩偶高 3 cm、宽 6–7 cm，所以夹着时玩偶最多垂到指尖下方约 3 cm；箱壁高 8 cm；各开度下的指尖距离），以及每个工具做什么。
**怎么抓，一个字都没写**，由模型自己规划。

### 2.4 模型和费用

通过 Anthropic API 调用 Claude Haiku 5.5（`claude-haiku-5-5`），自适应思考，effort 设为 `medium`，用官方的 Python SDK。价格是每百万 token 输入 $0.10、输出 $0.50。
每次调用带两张图（约 800 token）。一次 30 个动作的尝试**大约 $0.02**，40 次加起来远不到一美元。
密钥是用户自己设的用户级环境变量 `ANTHROPIC_API_KEY`，不会出现在仓库、日志和聊天记录里。

## 3. 基础模块

模型用桌面坐标思考，所以需要像素 ↔ 桌面的换算（§3.1–3.3）、夹爪的几何（§3.4），以及驱动机械臂的 FK / IK（§3.5–3.6）。

### 3.1 从像素到桌面：单应性

相机给的是二维图像，机械臂要的是三维坐标。一般情况下需要深度，但我们的情况很特殊：**玩偶和箱子都放在桌面上**，而桌面是一个平面。
一个平面经过透视投影到另一个平面（图像）上，两者之间正好由一个 3×3 矩阵 $H$ 对应，写成齐次坐标：

$$\begin{bmatrix} x \\ y \\ 1 \end{bmatrix} \sim H \begin{bmatrix} u \\ v \\ 1 \end{bmatrix},\qquad x = \frac{h_{11}u + h_{12}v + h_{13}}{h_{31}u + h_{32}v + h_{33}},\quad y = \frac{h_{21}u + h_{22}v + h_{23}}{h_{31}u + h_{32}v + h_{33}}$$

$H$ 只差一个比例因子，所以有 8 个自由度。每对"像素 ↔ 桌面点"给 2 个方程，**4 对就能解出来**，点更多就用最小二乘。
分母里的 $h_{31}, h_{32}$ 就是透视效果（近大远小）。所以**不需要深度相机**。

### 3.2 镜头畸变

Limit：单应性假设的是针孔相机，直线拍出来还是直线。我们的俯视相机是广角的，画面边缘的桌沿明显是弯的（桶形畸变）。
直接用单应性，离标定点远一点的地方会差 **1–3 cm**。所以：先去畸变，再乘 $H$。

用标准的径向畸变模型，以图像中心 $c$ 为原点（单位 $f$ = 400 像素）：

$$u_d = c + (u - c)\,\big(1 + k_1 r^2 + k_2 r^4\big),\qquad r = \frac{\lVert u - c \rVert}{f}$$

$u$ 是理想针孔相机看到的位置，$u_d$ 是我们相机实际看到的位置，$k_1 < 0$ 就是桶形畸变。我们要的是反过来（实际像素 → 理想像素），没有解析解，
所以用不动点迭代（$u \leftarrow c + (u_d - c) / (1 + k_1 r^2 + k_2 r^4)$，迭代 30 次）。$k_1, k_2$ 和 $H$ 用标定点**一起拟合**：
每试一组 $(k_1, k_2)$，先去畸变，再用最小二乘拟合 $H$，算误差；用 Nelder–Mead 在 $(k_1, k_2)$ 上搜索。结果：$k_1 = -0.47$，$k_2 = 0.28$。

### 3.3 触碰标定（不用示范）

1. 在玩偶和箱子会出现的桌面上贴一些深色的小胶带块，分散开，不要排成一条线，而且**俯视相机都要看得见**（被箱壁挡住的没用）。
2. 机械臂移开拍一张照片，脚本把每块胶带当作"比周围暗的一团"找出来（像素 = 这一团的中心）。
3. 遥操作从臂，用闭合的指尖碰每块胶带的中心；每碰一次，脚本记下关节角，用 FK（§3.5）算出指尖位置。

每块胶带就给出一对"像素 ↔ 桌面点"。一共碰了 16 个，用了 14 个：一块是灰色胶带，检测没找到；另一块在箱子最里面，机械臂伸到最长，那次碰偏了 3 cm。

| | |
|---|---|
| 拟合误差（中位数） | 约 6 mm |
| **留一误差**（拿掉一个点拟合，再去预测它；中位数） | **8.3 mm** |
| 桌面在机械臂坐标系里的高度（各次触碰指尖高度的中位数） | −0.7 cm |

留一误差才是实打实的数：它是拟合没见过的地方的误差。只用一开始那 6 块（全在画面一角）时有 1–3 cm，因为单应性只在有点的地方被约束住；
把点铺满整个工作区以后就好了。
玩偶宽 6–7 cm，夹爪最多张开 15 cm，所以 1 cm 左右在余量之内，剩下的偏差模型可以看着腕部相机自己修正。

PS：标定只在相机和机械臂底座都不动时有效。底座是夹住的；相机要是被碰歪了，就重新对齐（`scripts/align_camera.py`）或者重新标定一次（约 15 分钟）。

### 3.4 夹爪几何

SO-101 的夹爪是**一个固定指加一个活动指**。URDF 里的"指尖"（`gripper_frame_link`）在固定指上。
Limit：如果 `move_to` 定位的是这个点，模型对准玩偶中心，就会把固定指压在玩偶上，玩偶根本不在两指中间，每次都抓空。
所以 `move_to` 定位的是**当前开度下两个指尖的中点**：

- **距离**：开度 0 / 25 / 50 / 75 / 100 时，用尺子量两指尖之间的距离：0 / 4.5 / 9 / 12.7 / 15 cm（中间线性插值）。
- **方向**：从 URDF 看，活动指在 `gripper_link` 的 $+x$ 一侧，而指尖坐标系是它绕 $y$ 转了 180°，所以方向是指尖坐标系的 $-x$，再投影到桌面上。
- 中点 = 固定指尖 + 方向 × 距离 / 2。因为方向取决于最终的姿态，所以目标先换算一次、求解，再换算一次、再求解。

### 3.5 正运动学（FK）

机械臂是一串"连杆 + 关节"。URDF 给出每个关节相对父连杆的固定偏移（平移 + 旋转）和旋转轴。
所以指尖在底座坐标系里的位姿就是一串 4×4 齐次变换相乘：

$$T_{\text{tip}}(q) = \prod_{i=1}^{5} \Big( T_i^{\text{fixed}} \cdot \mathrm{Rot}(\text{axis}_i,\ q_i) \Big) \cdot T^{\text{tip}}$$

$T$ 左上角的 3×3 是姿态，右上角的 3×1 是位置。

PS：LeRobot 0.7 里 SO-101 的关节读数单位是度，0° = 标定范围的中点，和官方 `so101_new_calib.urdf` 的零点一致，所以直接代进去就行。
触碰标定顺便也是一次检验：碰在裸桌面上的 11 次，算出来的高度都一样，**−0.8 ± 0.2 cm**，覆盖了整个工作区。
如果零点错了或者某个轴反了，从一边到另一边的高度会差好几厘米。

### 3.6 逆运动学（IK）：阻尼最小二乘

IK 是反过来：给定"指尖在 $p^*$、夹爪朝下"，求关节角 $q$。SO-101 只有 5 个关节（wrist_roll 只让夹爪绕自身转，不改变指尖位置），
所以任意姿态做不到，但"位置 + 朝下"是能解的。

没有解析解，只能迭代。定义 6 维残差：

$$r(q) = \begin{bmatrix} p(q) - p^* \\ w \cdot \big(z_{\text{approach}}(q) - [0, 0, -1]^T\big) \end{bmatrix}$$

前 3 项是位置误差，后 3 项是"夹爪伸出的方向"和"正下方"的差，权重 $w = 0.05$。
每一步用数值雅可比 $J = \partial r / \partial q$（每个关节动 0.01°，看残差怎么变），然后

$$\Delta q = -J^T \big(J J^T + \lambda^2 I\big)^{-1} r$$

- 没有 $\lambda$ 就是 Gauss-Newton；但在奇异姿态附近（比如机械臂伸直）$JJ^T$ 接近奇异，$\Delta q$ 会爆掉。
  加上 $\lambda^2 I$，步长在奇异点附近会自动变小。这就是**阻尼最小二乘**（Levenberg-Marquardt 的思路）。
- PS：$\lambda$ 要和单位匹配：关节动 1°，指尖只动约 3 mm，所以雅可比的元素在 $10^{-3}$ 量级，$\lambda \approx 10^{-3}$。
- 每一步之后把角度裁到 URDF 的关节范围里。
- 高处（大约 13 cm 以上）5 个关节没法处处让夹爪保持竖直，这时 $w$ 降到 0.01，允许夹爪稍微倾斜。
- **初值**：从折叠的起始姿态出发，shoulder_lift 卡在 −100° 的极限上，求解器会卡住。所以还会从关节范围上的**均匀网格**出发
  （shoulder_lift 和 elbow_flex 取 −60 / −20 / 20 / 60°，wrist_flex 取 30 / 70°，shoulder_pan 对准目标），取最好的结果；几个一样好时，取离当前姿态最近的。

### 3.7 运动和安全层

这一层模型绕不过去；被拒绝的动作会作为错误信息返回给模型，让它换一个。

- **工作区**：x 5–38 cm，y −20–33 cm，z 0–25 cm（就是触碰标定过的范围）。
- **走直线**：沿直线每 1 cm 解一次 IK，每个点用前一个点的结果做初值，所以夹爪真的是直线运动（比如垂直落到玩偶上）。
  如果直线解不出来（比如从折叠的家位置出发），就用网格初值解出目标，再在关节空间插值过去；如果这样会往桌面方向蹭，就先垂直抬到 15 cm。
- **动之前先检查**：沿着要执行的运动每 2° 算一次 FK，指尖必须一直在桌面以上。
- **速度**：每个关节不超过 45°/s。
- **等到位**：舵机会落后于指令，所以每次运动后等关节到达目标 1.5° 以内（最多等 2 秒）再拍照；不然模型看到的是机械臂还没到的姿态，会误判。
- **家**：脚本启动时机械臂所在的折叠姿态（从机械臂上读的，不是从示范里取的）。每次尝试结束：先垂直抬到 15 cm，再回家。

## 4. 运行

都在仓库根目录、`lerobot` conda 环境里运行。

```powershell
python zero_shot/calibrate_touch.py                                  # 触碰胶带块（§3.3）
python zero_shot/fit_touch_calib.py outputs/zero_shot/calib_touch/<时间>   # -> zero_shot/camera_calib.json
python -m zero_shot.measure_gripper                                  # 开度 0..100 时的指尖距离（§3.4）
python -m zero_shot.agent --dry-run --frame data/Yufeng1216/rollout_eval_pi05:0   # 不连机械臂：用录好的画面，动作只规划不执行
python -m zero_shot.agent --trials 1 --step                          # 真机，每个动作前按回车
python -m zero_shot.agent --trials 5 --name vlm_agent                # 一组 5 次（共 8 组）；编号自动接续
python -m zero_shot.agent --trials 1 --name vlm_agent_demo --video   # 跑一次，同时按 30 fps 录两路相机（做 README 的 GIF 用）
```

`fit_touch_calib.py` 需要在触碰数据旁边放一个 `pairs.json`（第几次触碰 → `clean.jpg` 里那块胶带的像素）。每次尝试都会把每一步的图像和一个 `record.json`
（每个动作、模型自己的判断、用时、token、费用）存到 `outputs/zero_shot/<名字>/` 下。
两次尝试之间有 25 秒倒计时，用来把玩偶放到下一个点位（`--reset-time`），和 `robot.ps1 eval` 的复位时间一样，不用按键。

PS：关于协议：智能体每个动作都要调一次 API，一次尝试大约 1–3 分钟，比训练出来的策略的 30 秒上限长得多。
所以它的上限改成 **25 次模型调用**（一次调用里可以有好几个工具调用，比如先移动再闭合），而不是 30 秒，同时记录用时；这是它和 [08_evaluation.zh-CN.md](08_evaluation.zh-CN.md) 唯一不同的地方。

## 5. 结果

**29/40**（72.5%，95% 区间 57–84%）；3 次抓起没放进，8 次没抓起。各点位 ① 7 · ② 6 · ③ 7 · ④ 4 · ⑤ 5（满分 8）。完整记录：[results/vlm_agent.zh-CN.md](../results/vlm_agent.zh-CN.md)；
每一步的图像和决定：[`Yufeng1216/vlm_agent_eval_logs`](https://huggingface.co/datasets/Yufeng1216/vlm_agent_eval_logs)。

- **除了 ACT，和训练过的策略打平。** 好于 ACT（14/40，p = 0.002）；和 Diffusion（25/40）、SmolVLA（26/40）、π₀.₅（34/40）在每个 40 次的样本下分不出差别。
- **慢。** 每次中位数 100 秒（45–252 秒）、11.5 次模型调用、$0.03；大部分时间是模型在思考、机械臂停着。训练出来的策略是 30 Hz 直接出动作。
- **④ 最弱**，那里紧挨着箱壁：手指要么被箱壁挡住够不到，要么把玩偶推开，模型就一直重试。
- **对自己很诚实。** 38 次调用了 `done`，其中 37 次自己的判断和实际结果一致；只有一次玩偶不在箱子里，它却报告成功；另外两次用完了调用次数。

Limit：动作空间固定成夹爪竖直、手腕不转（§3.6），模型拿到的几何信息是手工量的（§3）。
所以这里的"免训练"指的是不用机器人数据、不用任务示范，而不是"不需要工程"：标定、夹爪测量和安全层，才是让通用模型能用起来的东西。
