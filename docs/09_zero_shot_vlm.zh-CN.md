# 09 · 免训练基线：视觉语言模型 + 逆运动学

[English](09_zero_shot_vlm.md) · **简体中文**

## 1. 为什么要做这组实验

前面四个策略（ACT、Diffusion、SmolVLA、π₀.₅）都是**端到端模仿学习**：用 50 条示范学"图像 → 动作"。
另一条路线是**不训练**：让通用的视觉语言模型（VLM）看懂场景，再用传统的几何计算和固定的动作脚本去执行。

把两条路线放在**同一个任务、同一套评估协议**下比，回答一个很实际的问题：

> 50 条人工示范带来的提升，到底比"现成大模型 + 几何计算"多多少？各自在什么情况下失败？

这里有两个版本，区别在 VLM 决定多少事：

| | A. VLM 指点 + 固定抓取脚本（第 2–8 节，已实现） | B. VLM 智能体（第 9 节，下一步） |
|---|---|---|
| VLM | Qwen3-VL-2B，本地 | Claude Haiku 5.5，云端 API |
| VLM 决定什么 | 只决定玩具和盒子在哪 | 全部：抓哪里、抬多高、怎么走、什么时候松手、要不要重来 |
| 人写了什么 | 整个动作脚本 | 没有任务逻辑：IK + 安全检查只负责把"夹爪移到 (x, y, z)"翻译成关节角 |
| 闭环 | 开环，开始时只看一次 | 闭环，每动一次都重新看 |

PS：两个版本都不训练模型。但版本 A 从示范里取了好几个数（第 7.1 节），所以它是"免训练"，不是"不用示范"。

## 2. 流水线

```
俯视相机画面（640×480）
   │
   ▼  ① 感知：VLM（Qwen3-VL-2B-Instruct，本地运行）
   │     提示词："Point to the blue plush toy" / "Point to the center of the cardboard box"
   │     输出：像素坐标 (u, v)
   ▼  ② 像素 → 桌面坐标：单应性矩阵 H（用示范数据标定；玩具和盒子各一个）
   │     (u, v) ──H──▶ (x, y)，机械臂底座坐标系，单位米
   ▼  ③ 逆运动学（IK）：SO-101 的 URDF + 阻尼最小二乘
   │     "夹爪尖到 (x, y, z)、夹爪朝下" → 5 个关节角度
   ▼  ④ 固定的动作脚本（开环执行）
         张开 → 玩具上方 6 cm → 竖直下降 → 闭合 → 竖直抬到 11 cm → 再抬到约 17 cm →
         在这个高度平移到盒子上方 → 降到 11 cm → 松开 → 回到起始姿态
```

下面一步步讲每一块在做什么。

## 3. 感知：VLM 怎么"指"出一个点

### 3.1 Qwen3-VL 的结构

Qwen3-VL-2B 和 SmolVLM、PaliGemma 一样，是 "ViT + 投影层 + 语言模型"：

1. **视觉编码器**（ViT，24 层，宽 1024，patch 16）：它支持**任意分辨率**，不需要先缩放成正方形。640×480 的图切成 40×30 = 1200 个 patch。
   位置编码用的是 2D 的旋转位置编码（RoPE），所以模型知道每个 patch 在图上的行和列。
2. **Merger**：相邻 2×2 个 patch 合并成一个 token（和 SmolVLM 的 pixel shuffle 是同一个思路），1200 → **300 个视觉 token**，再投影到语言模型的宽度。
3. **语言模型**（Qwen3，28 层，宽 2048，GQA 16/8 头）：视觉 token 和文字 token 拼成一个序列，**自回归**地生成回答。

### 3.2 坐标就是文字

关键在于：Qwen3-VL 在预训练时见过大量"指出物体位置"的数据（grounding），所以它能**用文字输出坐标**。我们的提示词是：

```
Point to the blue plush toy in the image. Answer only with JSON in this format: [{"point_2d": [x, y], "label": "toy"}]
```

它会回答 `[{"point_2d": [512, 233], "label": "toy"}]`。这些数字就是一个个普通的 token，和生成一句话没有区别。
PS：Qwen3-VL 输出的是 **0–1000 的相对坐标**，不是像素，要乘上图像宽高再除以 1000。

Limit：生成的数字是离散的 token，所以精度有上限；而且模型只给一个点，不给物体的大小和朝向。不过对"玩具大概在哪"已经够用了（第 6 节）。

### 3.3 为什么选它

| 考虑 | 理由 |
|---|---|
| 能直接输出坐标 | 不用再接一个检测模型 |
| 2B 参数 | bf16 约 4 GB，放得进 8 GB 显存，每次询问约 1.7 s |
| 本地运行 | 不花钱，也不会把房间的画面发到外部服务器 |

## 4. 几何：从像素到桌面

### 4.1 单应性矩阵（homography）

相机拍到的是 2D 画面，机械臂要的是 3D 坐标。一般来说这需要深度，但我们的情况特殊：**玩具一直躺在桌面上**，桌面是一个平面。
而一个平面经过透视投影到另一个平面（图像），这个映射正好是一个 3×3 矩阵 $H$，在齐次坐标下：

$$\begin{bmatrix} x \\ y \\ 1 \end{bmatrix} \sim H \begin{bmatrix} u \\ v \\ 1 \end{bmatrix},\qquad x = \frac{h_{11}u + h_{12}v + h_{13}}{h_{31}u + h_{32}v + h_{33}},\quad y = \frac{h_{21}u + h_{22}v + h_{23}}{h_{31}u + h_{32}v + h_{33}}$$

$H$ 只差一个整体缩放，所以有 8 个自由度。每对"像素 ↔ 桌面点"给 2 个方程，**4 对点就能解出来**，更多的点用最小二乘。
分母里的 $h_{31}, h_{32}$ 就是透视效果（近大远小）。所以**不需要深度相机**，也不需要知道相机内参。

### 4.2 对应点从哪来：直接用示范数据

要解 $H$ 就要一批对应点。我们没有单独做标定，而是直接从 50 条示范里拿：

- **像素**：每条示范的第一帧里，蓝色玩具是白桌面上唯一的蓝色物体，所以用 HSV 颜色阈值 + 最大连通域，就能求出它的中心 $(u, v)$；
- **桌面点**：夹爪合上抓住玩具的那一刻，把记录下来的关节角度代入**正运动学（FK，第 4.3 节）**，就能算出夹爪尖的 $(x, y)$。

玩具在这两个时刻之间没动过，所以每条示范就是一组对应点。`cv2.findHomography` 用 **RANSAC** 求 $H$：
随机抽 4 对点解一个 $H$，看多少点和它吻合（误差 < 1.5 cm），重复很多次，取吻合最多的那个。这样个别检测错的点会被自动剔除。

PS：桌面抓取点都挤在 5 个标记点附近（约 10×10 cm），离得远的地方 $H$ 外推误差很大（到盒子那边差了 24 cm）。
所以盒子用第二个映射 `H_pixel_to_place`：再加上示范里"松手那一刻"的对应点（画面里的玩具 ↔ FK 算的夹爪位置）一起拟合。
松手时玩具离桌面约 9 cm，会有几厘米视差，但盒口约 20 cm 宽，够用。

### 4.3 正运动学（FK）

机械臂是一串"连杆 + 关节"。URDF 文件里写了每个关节相对上一个连杆的固定偏移（平移 + 旋转）和转轴。
所以夹爪尖在底座坐标系里的位姿就是一串 4×4 齐次变换相乘：

$$T_{\text{tip}}(q) = \prod_{i=1}^{5} \Big( T_i^{\text{fixed}} \cdot \mathrm{Rot}(\text{axis}_i,\ q_i) \Big) \cdot T^{\text{tip}}$$

$T$ 的左上 3×3 是朝向，右上 3×1 是位置。

PS：LeRobot 0.7 里 SO-101 的关节读数就是"度"，0° = 标定范围的中点，和官方 `so101_new_calib.urdf` 的零点一致，所以可以直接代进去。
我们用示范验证过：35 次桌面抓取时，FK 算出的夹爪尖高度是 **−0.8 ± 1.0 cm**（夹爪尖略压进软桌垫），抓取位置聚成 5 簇，正好对应 5 个胶带标记点。
零点或者方向错了的话，这些数会乱掉。

### 4.4 逆运动学（IK）：阻尼最小二乘

IK 是反过来：给定目标"夹爪尖在 $p^*$、夹爪朝下"，求关节角 $q$。SO-101 只有 5 个关节（其中 wrist_roll 只让夹爪绕自身转，不影响位置），
所以没法任意指定姿态，但"位置 + 朝下"这个约束是解得出来的。

没有闭式解，所以用迭代。定义残差（6 维）：

$$r(q) = \begin{bmatrix} p(q) - p^* \\ w \cdot \big(z_{\text{approach}}(q) - [0, 0, -1]^T\big) \end{bmatrix}$$

前 3 维是位置误差，后 3 维是"夹爪接近方向"和"竖直向下"的差，$w = 0.05$ 是权重。每一步用数值雅可比 $J = \partial r / \partial q$（每个关节动 0.01° 看残差变多少），然后

$$\Delta q = -J^T \big(J J^T + \lambda^2 I\big)^{-1} r$$

- 没有 $\lambda$ 的话这就是高斯-牛顿法；但机械臂接近奇异姿态（比如手臂伸直）时 $JJ^T$ 接近不可逆，$\Delta q$ 会爆掉。
  加上 $\lambda^2 I$ 之后，步长在奇异点附近会自动变小。这就是**阻尼最小二乘**（Levenberg-Marquardt 的思路）。
- PS：$\lambda$ 的大小要和单位匹配：关节动 1° 夹爪尖只移动约 3 mm，雅可比的元素在 $10^{-3}$ 量级，所以 $\lambda \approx 10^{-3}$。
- 每一步结束后把关节角裁到 URDF 的限位里。
- 初值很重要：从收拢的起始姿态出发，shoulder_lift 正好卡在 −100° 的限位上，会卡住。所以用示范里几种典型的抓取姿态做初值，取误差最小的那个。

结果：桌面目标误差 **0.1 mm**，夹爪竖直向下。

## 5. 执行：固定的动作脚本

`run_grasp.py` 把 IK 解出的几个关键姿态串起来：

```
起始姿态 → 玩具上方 6 cm（张开） → 竖直下降（每 0.5 cm 解一次 IK，保证是直线下降） → 闭合
        → 竖直抬到 11 cm → 再抬到约 17 cm → 在这个高度平移到盒子上方 → 降到 11 cm → 松开 → 回到起始姿态
```

为什么搬运时要抬到 17 cm：玩具挂在夹爪下面好几厘米。示范里人搬运时夹爪尖平均抬到 13.7 cm（90% 低于 16.6 cm），所以 17 cm 在所有示范里都能越过盒壁。
PS：高于约 13 cm 时，5 个关节的机械臂已经没法让夹爪保持竖直朝下，所以搬运那几个姿态放宽了 IK 的容差（几厘米）。它们都在空中，下面的路径检查仍然会把关。

- 两个关键姿态之间在关节空间里线性插值，以 30 Hz 发给 `SO101Follower.send_action()`，默认每个关节最快 20°/s。
  这和学习型策略用的是**完全相同的底层接口和标定文件**，对比才公平。
- **动之前先检查**：目标在合理区域内、IK 误差够小、整条插值路径上每一个点的夹爪尖都不低于桌面以下 2.5 cm（搬运段不低于 14 cm，免得玩具撞盒壁）。
  任何一条不满足就不动。
- `--step` 每段停下来等你按 Enter；Ctrl+C 时先慢慢回到起始姿态再断开。

离线检查：把玩具放在每条示范的抓取点、盒子放在它的松手点，**35/35** 都能规划出安全路径；搬运时夹爪尖最低 16.6 cm；一次完整动作约 25 s。

## 6. 离线验证结果

代码在 [`zero_shot/`](../zero_shot/)，讲解见 [code_walkthrough.zh-CN.md](code_walkthrough.zh-CN.md) 第 14 节。

| 模块 | 怎么测 | 结果 |
|---|---|---|
| FK | 示范里抓取时刻的夹爪尖高度（`python -m zero_shot.check_fk`） | −0.8 ± 1.0 cm，5 簇对应 5 个标记点 |
| IK | 桌面目标 | 误差 0.1 mm，夹爪竖直向下；上方 10 cm 悬停误差 4–6 mm（腕关节到了 95° 限位） |
| 玩具映射 `H_pixel_to_table` | 35 组对应点，25 个 RANSAC 内点 | 由像素推桌面位置的误差中位 0.6 cm，最大 1.4 cm |
| 盒子映射 `H_pixel_to_place` | 加上松手时刻的对应点 | 松手处误差中位 1.3 cm |
| VLM 指向玩具 | 50 条示范的第一帧，和颜色检测的中心比 | 50/50 给出坐标；误差中位 0.5 cm、90% 分位 1.0 cm、最大 1.5 cm |
| VLM 指向盒子中心 | 同上 | 每次都落在盒子里，前后相差约 3 cm（"中心"本身就不明确），放进盒子够用 |

⇒ **感知和几何本身不是瓶颈**（误差约 1 cm，远小于玩具的大小）。真机上的成败主要取决于固定的抓法能不能夹住软玩具，以及开环执行时玩具会不会被碰动。

## 7. 已知局限（报告里要写明）

### 7.1 版本 A 从示范里取了什么

没有训练模型，但示范被用来做标定和定参数：

| 用在哪 | 从示范里取了什么 | 性质 |
|---|---|---|
| 像素 → 桌面的两个映射 | 第一帧里玩具的像素 + 抓取 / 松手时 FK 算出的夹爪位置 | 标定 |
| `GRASP_Z` −0.8 cm、`PLACE_Z` 11 cm、`CARRY_Z` 17 cm | 抓取、松手、搬运时夹爪尖的高度 | 参数 |
| `REST` | 示范第一帧关节角的平均值 | 参数 |
| IK 初值、`WORKSPACE` | 典型的抓取姿态；抓取点和松手点的范围 | 启发、安全限制 |

另外，张口、速度、搬运高度这些设置是看了真机尝试之后调的，相当于在测试条件上调参。
干净的做法是：相机-机械臂标定不用示范（用夹爪尖碰桌上几个点，在图上标出来），高度用尺子量，40 次评估前冻结所有设置。版本 B 就按这个做。

### 7.2 其他局限

- **只有俯视 RGB，没有深度**：假设物体都在桌面上，抓取高度固定。我们的任务满足这个条件；物体叠起来或者悬空就不成立了。
- **固定的抓法**：只会"从正上方竖直夹"。对软的毛绒玩具，可能不如学出来的策略。这正是值得报告的对比点。
- **开环执行**：动作过程中不看画面，被碰到或者滑掉了也不知道。
- **依赖底座位置**：所有目标都在底座坐标系里算，映射也是按底座原来的位置标定的。底座挪 1 cm，夹爪就会"准确地"落到偏 1 cm 的地方。

## 8. 运行和评估

```powershell
python -m zero_shot.run_grasp --dry-run                         # 只拍照、指向、规划，机械臂不动
python -m zero_shot.run_grasp --speed 15 --open 60              # 真机，自动执行一次
python -m zero_shot.run_grasp --trials 40 --name zero_shot      # 正式评估：每次结束后输入结果
```

每次试验在 `outputs/zero_shot/<name>/` 留下：`attempts.csv`（像素、桌面坐标、耗时、结果，以及下降到底和闭合后**实测**的关节角和夹爪尖高度）、
标注了 VLM 指向的照片，以及"玩具上方 / 最低点 / 闭合后"三个时刻的俯视和腕部照片。

可调参数：`--open`（张口 0–100，示范平均约 39）、`--close-early`（离抓取高度还有几厘米时就开始合拢，对软玩具有帮助）、`--grasp-z`（抓取高度，cm）、`--speed`（°/s）。

评估和其他策略**完全一样**：5 个点 × 8 次 = 40 次，同样的成功 / 部分成功 / 失败标准（[08_evaluation.zh-CN.md](08_evaluation.zh-CN.md)）。
另外记下每次的 VLM 耗时和运动耗时，失败时归因到：指向错 / IK 无解 / 抓空 / 搬运中掉落 / 放偏。

## 9. 下一步：版本 B，由 VLM 做全部决策的智能体

目标：一个没在机器人数据上训练过的通用模型，自己决定整个任务怎么做，每动一次都重新看一眼相机。

**为什么不让它直接输出关节角？** 没训练过的模型不知道这台机械臂的运动学，只能看一眼、动一点，几十步地挪过去，这就成了长程问题，要很大的模型。
换成笛卡尔接口，同一个任务只要 5–10 个决策（到玩具上方、下降、合上、抬起、移到盒子上方、松开），小而便宜的模型就能胜任。
这里的 IK 相当于驱动（像汽车方向盘把"往左"变成车轮转角），不做任何任务决策。论文里的免训练系统也是这样搭的
（Code as Policies、VoxPoser、MOKA、ReKep、Gemini Robotics-ER）：大模型做决策，下面接一个通用的笛卡尔 / IK 执行层。

**给模型的工具**（只有这些）：

| 工具 | 作用 |
|---|---|
| `look()` | 返回俯视图、腕部图和夹爪当前位置 (x, y, z) |
| `move_to(x, y, z)` | 把夹爪尖移到那里、朝下（IK + 关节限速 + 和版本 A 一样的路径检查） |
| `gripper(opening)` | 张开（0–100）或合上夹爪 |
| `done(result)` | 结束这次尝试 |

**模型**：通过 Anthropic API 调用 Claude Haiku 5.5（能看图、能调用工具；输入 / 输出每百万 token $0.10 / $0.50；每次尝试约十次调用，
40 次加起来远不到 1 美元）。账号和密钥由用户自己设置（`ant auth login` 或 `ANTHROPIC_API_KEY`），不写进仓库。

**计划**：
1. 不用示范做相机-机械臂标定；盒子和玩具的高度用尺子量。
2. 写智能体循环，先用录好的画面离线测（不接机械臂）。
3. 真机试几次，然后冻结提示词和设置，按 [08_evaluation.zh-CN.md](08_evaluation.zh-CN.md) 的协议测 40 次。
